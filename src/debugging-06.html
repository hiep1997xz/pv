Debug & Fix MIDDLE 06 / 08
Race condition khi fetch
?Gõ tìm kiếm nhanh lại ra kết quả của từ khoá cũ, vì sao?
?Chống double submit form thì làm ở client hay server?
💡 Trả lời
  • Dấu hiệu: ô search gõ nhanh, kết quả hiển thị lại là của từ khoá trước đó; bấm chuyển tab liên tục thì dữ liệu tab cũ nhấp nháy đè lên tab mới.
  • Nguyên nhân: mỗi lần tham số đổi là một request mới, nhưng response về không theo thứ tự gửi. Request cũ về sau sẽ ghi đè state của request mới.
  • Sửa tối thiểu: cờ ignore trong effect, cleanup đặt ignore = true — response cũ về vẫn bị bỏ qua, không cần huỷ request.
  • Tốt hơn: AbortController huỷ hẳn request cũ, đỡ tốn băng thông và kết nối. Nhớ bỏ qua AbortError, đó là hành vi mong muốn chứ không phải lỗi.
  • Cùng một gốc là double submit: bấm gửi hai lần tạo hai đơn. Khoá nút bằng isSubmitting ở client, nhưng phải có idempotency key ở server mới chắc.
// ❌ gõ nhanh: response của "ab" về sau "abc" → hiện sai kết quả
useEffect(() => {
  fetch(`/api/search?q=${q}`).then(r => r.json()).then(setList);
}, [q]);

// ✅ AbortController: huỷ request cũ khi q đổi hoặc unmount
useEffect(() => {
  const ac = new AbortController();
  fetch(`/api/search?q=${q}`, { signal: ac.signal })
    .then(r => r.json())
    .then(setList)
    .catch(e => { if (e.name !== 'AbortError') setErr(e); });

  return () => ac.abort();
}, [q]);
⚠ Bẫy phỏng vấn: Chỉ debounce ô input là chưa đủ. Debounce giảm số lượng request chứ không quyết định thứ tự response — mạng chậm một nhịp là request cuối vẫn có thể về trước. Phải có ignore hoặc abort mới chắc.
💬 Nói thêm để ghi điểm: React Query / SWR lo sẵn việc này: cache theo query key, tự dedupe request trùng và chỉ nhận kết quả của key đang active. Trả lời "dùng React Query" thì phải nói kèm vì sao nó an toàn, không thì thành học vẹt.
