?Vì sao không được dùng float để lưu tiền?
?timestamptz khác timestamp ở chỗ nào?
💡 Trả lời
  • Tiền tuyệt đối không dùng float. float8 là nhị phân, không biểu diễn chính xác 0.1 — cộng dồn là lệch. Dùng numeric(12,2), hoặc bigint theo đơn vị nhỏ nhất.
  • timestamptz là thời điểm tuyệt đối (lưu UTC, hiển thị theo timezone của session). timestamp không timezone — chỉ là ngày giờ trần, hai server khác múi giờ hiểu khác nhau.
  • text thay varchar(n): ở Postgres hai kiểu lưu y hệt nhau, varchar(n) không nhanh hơn, chỉ là text kèm một ràng buộc độ dài mà sau này muốn nới ra thì phải ALTER.
  • jsonb thay json: json giữ nguyên văn bản gốc nên phải parse lại mỗi lần đọc. jsonb đã parse sẵn thành nhị phân — truy vấn nhanh, index được bằng GIN.
  • enum gọn và nhanh nhưng thêm giá trị phải ALTER TYPE, bỏ giá trị thì rất phiền, và không gắn được thuộc tính kèm theo. Tập giá trị hay đổi → bảng tra + FK.
CREATE TABLE payments (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  amount      numeric(12,2) NOT NULL,   // hoặc bigint, đơn vị xu
  currency    char(3) NOT NULL,
  meta        jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at  timestamptz NOT NULL DEFAULT now()
);

// ❌ float là nhị phân: cộng dồn lệch xu, đối soát không khớp
SELECT 0.1::float8 + 0.2::float8;    // 0.30000000000000004
// ✅ numeric tính đúng theo hệ thập phân
SELECT 0.1::numeric + 0.2::numeric;  // 0.3
⚠ Bẫy phỏng vấn: Lưu tiền bằng float thì lỗi chỉ lộ sau vài tháng: tổng báo cáo lệch với cổng thanh toán vài nghìn đồng, không truy được dòng nào sai. Sửa thì phải đổi kiểu cột và migrate lại toàn bộ bảng giao dịch.
