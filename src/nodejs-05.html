💡 Trả lời
  • Session: server giữ trạng thái, thu hồi tức thì bằng cách xoá bản ghi. JWT: stateless, server chỉ kiểm chữ ký — đổi lại rất khó thu hồi trước khi token hết hạn.
  • Cách làm thực tế: access token sống ngắn (5–15 phút) cộng refresh token dài hạn lưu trong DB để thu hồi được. Đăng xuất là xoá refresh token, không xoá được access token.
  • Lưu token trong cookie httpOnly kèm Secure và SameSite — JS không đọc được nên XSS khó lấy. Để ở localStorage thì một lỗ XSS là mất sạch.
  • Mật khẩu phải hash bằng thuật toán chậm có chủ đích: bcrypt, scrypt hoặc argon2, và có salt riêng từng người. SHA-256 thiết kế để nhanh, GPU dò hàng tỉ mật khẩu mỗi giây.
  • Phân quyền kiểm ở server, trên từng request — ẩn nút trên UI chỉ là trang trí. Endpoint đăng nhập phải có rate limit theo cả IP lẫn tài khoản để chặn dò mật khẩu.
// ❌ SHA-256 quá nhanh → GPU dò hàng tỉ mật khẩu mỗi giây
const bad = createHash('sha256').update(pw).digest('hex');

// ✅ bcrypt tự sinh salt riêng; cost 12 = chậm có chủ đích
const hash = await bcrypt.hash(pw, 12);
const ok = await bcrypt.compare(pw, user.passwordHash);

const access = jwt.sign({ sub: user.id, role: user.role },
  process.env.JWT_SECRET, { expiresIn: '15m' });

res.cookie('rt', refreshToken, {   // ✅ JS phía client không đọc được
  httpOnly: true, secure: true, sameSite: 'strict', path: '/auth',
});
⚠ Bẫy phỏng vấn: Bẫy kinh điển: nhét role vào JWT rồi tin nó mãi. Hạ quyền một user xong, token cũ vẫn mang role: "admin" cho tới lúc hết hạn. Thao tác nhạy cảm phải tra lại quyền trong DB, đừng đọc từ payload.
