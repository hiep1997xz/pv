Promise · async/await · xử lý lỗi
?Promise.all và allSettled khác nhau thế nào?
?Xử lý lỗi với async/await sao cho đúng?
💡 Trả lời
  • Promise có 3 trạng thái: pending → fulfilled hoặc rejected. Chuyển đúng một lần rồi khoá vĩnh viễn. then luôn trả về promise mới nên chain được.
  • async luôn trả về promise. await chỉ tạm dừng hàm đó, không chặn luồng chính. try/catch quanh await bắt được reject; thiếu await thì lỗi rơi ra ngoài try.
  • Promise.all reject ngay khi một cái hỏng (fail-fast) — các cái còn lại vẫn chạy nhưng kết quả bị bỏ. allSettled luôn resolve, trả mảng {status, value}.
  • race theo cái xong trước, kể cả khi cái đó reject. any lấy cái fulfilled đầu tiên, hỏng hết mới ném AggregateError.
  • Tuần tự vs song song: await a(); await b(); chạy nối tiếp. Hai việc độc lập thì gom vào Promise.all để chạy cùng lúc — đây là câu hỏi tối ưu rất hay bị hỏi.
// ❌ tuần tự: 200ms, dù hai việc chẳng liên quan gì nhau
const u1 = await getUser();
const p1 = await getPosts();

// ✅ song song: 100ms
const [u2, p2] = await Promise.all([getUser(), getPosts()]);

// ❌ thiếu await → reject lọt ra ngoài, thành unhandled rejection
try { run(); } catch (e) { console.log('không bắt được'); }

// ✅ có await thì reject mới rơi đúng vào catch
try { await run(); } catch (e) { console.log(e.message); }

const rs = await Promise.allSettled([getUser(), getPosts()]);
console.log(rs.map(r => r.status));   // ['fulfilled', 'rejected']
⚠ Bẫy phỏng vấn: Sai lầm phổ biến nhất: arr.forEach(async ...). forEach không đợi promise nên hàm chạy tiếp ngay, lỗi bên trong thành unhandled rejection. Phải dùng for...of + await, hoặc Promise.all(arr.map(f)).
💬 Nói thêm để ghi điểm: Promise bị reject mà không ai catch → Node hiện tại mặc định kill process, browser thì log unhandledrejection. Luôn đóng chain bằng catch, và bắt sự kiện toàn cục để log lại những ca lọt lưới.
