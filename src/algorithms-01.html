Big-O · cách phân tích độ phức tạp
?O(n log n) nghĩa là gì, bạn gặp nó ở đâu?
?includes đặt trong vòng for thì độ phức tạp bao nhiêu?
💡 Trả lời
  • Big-O mô tả chi phí tăng thế nào khi n lớn. Bỏ hằng số và số hạng nhỏ: 3n + 100 vẫn là O(n).
  • Thang quen thuộc: O(1) tra Map · O(log n) binary search · O(n) quét một lượt · O(n log n) sort · O(n²) hai vòng lồng nhau.
  • Vòng lặp lồng nhau thì nhân (n×n = O(n²)); vòng lặp nối tiếp thì cộng, mà cộng xong vẫn lấy số hạng lớn nhất: O(n)+O(n) = O(n).
  • Space complexity chỉ đếm bộ nhớ cấp phát thêm, không tính mảng đầu vào. Đệ quy tốn O(chiều sâu) cho call stack dù không tạo mảng nào.
  • Method mảng JS: includes · indexOf · find là O(n) · sort là O(n log n) · push/pop là O(1) · shift/unshift là O(n).
// ❌ O(n²): 2 vòng lồng nhau, n = 10.000 → ~50 triệu phép so sánh
function hasDup(a) {
  for (let i = 0; i < a.length; i++)
    for (let j = i + 1; j < a.length; j++)
      if (a[i] === a[j]) return true;
  return false;
}
// ✅ O(n) thời gian, đổi lại O(n) bộ nhớ — Set tra cứu O(1) trung bình
const hasDupFast = a => new Set(a).size !== a.length;
console.log(hasDup([1, 2, 3, 1]), hasDupFast([1, 2, 3, 1])); // true true

// ❌ includes là O(n); đặt trong vòng lặp → tổng O(n²)
const uniq = a => a.reduce((r, x) => r.includes(x) ? r : [...r, x], []);
// ✅ Set một lượt, O(n)
console.log(uniq([1, 2, 2]), [...new Set([1, 2, 2])]);
⚠ Bẫy phỏng vấn: Bẫy đếm sai hay gặp nhất: “em quét mảng một lần nên O(n)”. Nhưng bên trong có includes hoặc indexOf — mỗi lần gọi đã quét lại cả mảng. Tổng thật là O(n²). [...r, x] trong reduce cũng vậy.
