Docker Compose · Nhiều môi trường
?depends_on có đảm bảo database đã sẵn sàng không?
?Tách cấu hình dev và production thế nào?
💡 Trả lời
  • depends_on mặc định chỉ đợi container khởi động, không đợi dịch vụ nhận được kết nối. Phải thêm healthcheck và condition: service_healthy.
  • Kể cả có healthcheck, app vẫn nên tự retry khi kết nối DB. Container có thể bị khởi động lại bất cứ lúc nào, không chỉ lúc mới bật.
  • Tách file: compose.yaml là phần chung, compose.override.yaml tự nạp cho dev, production chạy với -f chỉ rõ từng file.
  • Biến môi trường để trong env_file, và file .env không bao giờ commit. Bí mật thật thì dùng secrets, đừng nhét vào environment.
  • profiles để bật tắt dịch vụ phụ như worker hay mail server mà không cần đẻ thêm file compose riêng.
services:
  db:
    image: postgres:17
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 10
  api:
    build: .
    depends_on:
      db:
        condition: service_healthy   # ✅ đợi DB sẵn sàng thật
    env_file: [.env]
    restart: unless-stopped
⚠ Bẫy phỏng vấn: depends_on không đợi dịch vụ sẵn sàng, nó chỉ đợi container bật lên. API khởi động trước khi Postgres nhận kết nối là crash ngay. Trả lời thiếu ý này là mất điểm ở đúng câu Compose.
💬 Nói thêm để ghi điểm: Phân biệt restart: unless-stopped và always: unless-stopped sẽ không tự bật lại nếu bạn chủ động dừng container. Và docker compose v2 có dấu cách đã thay docker-compose cũ.
