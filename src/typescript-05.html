Narrowing · type guard · discriminated union
?Type guard tự viết khác gì typeof thường?
?Làm sao để switch báo lỗi khi thêm case mới?
💡 Trả lời
  • TS narrow tự động qua typeof (primitive), instanceof (class), in (có field), so sánh literal, và Array.isArray.
  • Type guard tự viết trả về x is Foo. TS tin lời khai đó chứ không kiểm chứng — logic bên trong sai thì narrow sai mà compiler vẫn im.
  • Discriminated union: mỗi nhánh có chung một field literal (kind, type, status), nhờ đó switch trên field ấy narrow được từng nhánh.
  • Exhaustive check: ở nhánh default gán giá trị vào một biến kiểu never. Thêm nhánh mới mà quên xử lý là lỗi compile, không phải bug lặng lẽ.
  • Assertion function asserts x is T: ném lỗi nếu sai, sau lời gọi thì narrow cho cả phần còn lại. Nếu gán vào biến thì phải khai type tường minh.
type Shape =
  | { kind: 'circle'; r: number }
  | { kind: 'rect'; w: number; h: number };

function area(s: Shape): number {
  switch (s.kind) {
    case 'circle': return Math.PI * s.r ** 2;
    case 'rect':   return s.w * s.h;
    default: {
      // ✅ thêm kind mới mà quên case → dòng dưới lỗi compile
      const _never: never = s;
      return _never;
    }
  }
}
⚠ Bẫy phỏng vấn: Type guard chỉ là lời hứa: khai x is User nhưng bên trong mới kiểm !!x thì TS vẫn tin tuyệt đối. Narrow sai kiểu này không có một cảnh báo nào, bug lòi ra tận runtime.
💬 Nói thêm để ghi điểm: Truthiness narrowing có bẫy với số và chuỗi: if (count) loại luôn 0, if (s) loại luôn chuỗi rỗng. Với number|undefined thì phải so sánh !== undefined mới đúng.
