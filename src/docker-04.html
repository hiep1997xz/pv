Multi-stage build · Giảm kích thước image
?Multi-stage build giải quyết vấn đề gì?
?Làm sao giảm image 1.2GB xuống vài chục MB?
💡 Trả lời
  • Một stage để build (có compiler, devDependencies), một stage để chạy chỉ copy kết quả sang. Công cụ build không lọt vào image cuối.
  • COPY --from=builder chỉ lấy đúng thứ cần: thư mục dist, binary đã compile, hoặc node_modules bản production.
  • Base image nhẹ dần: node:22 khoảng 1.1GB → node:22-alpine khoảng 150MB → distroless hoặc scratch cho binary Go/Rust, chỉ vài chục MB.
  • Image nhỏ không chỉ đỡ tốn đĩa: kéo về nhanh hơn, deploy nhanh hơn, và ít lỗ hổng hơn vì không còn shell, package manager hay compiler để mà khai thác.
  • Cần debug stage giữa thì dừng lại ở đó bằng docker build --target builder.
FROM node:22-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci                  # có devDependencies để build
COPY . .
RUN npm run build

FROM node:22-alpine AS runtime
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --omit=dev       # ✅ chỉ dependency chạy thật
COPY --from=builder /app/dist ./dist
USER node                   # ✅ không chạy bằng root
CMD ["node", "dist/index.js"]
⚠ Bẫy phỏng vấn: Chỉ đổi sang alpine chưa chắc đủ. Nếu stage chạy vẫn npm ci đầy đủ cả devDependencies thì image vẫn phình. Phải tách stage thì công cụ build mới thật sự không lọt vào image cuối.
💬 Nói thêm để ghi điểm: Alpine dùng musl thay cho glibc, nên vài thư viện native như sharp, bcrypt, canvas có thể lỗi hoặc chậm bất thường. Gặp vấn đề thì đổi sang node:22-slim chứ đừng cố vá.
