Bảng 10.000 dòng · Server-side · URL
?Bảng 10.000 dòng thì sort và filter đặt ở đâu?
?Chọn nhiều dòng qua nhiều trang thì lưu thế nào?
💡 Trả lời
  • Sort/filter/paginate ở server. Client-side chỉ đúng khi toàn bộ dữ liệu đã nằm sẵn ở client; tải 10.000 dòng là vài MB JSON, riêng khâu parse đã chặn main thread.
  • Virtualization dòng (TanStack Virtual, react-window) chỉ render khoảng 30 dòng trong viewport cộng overscan. Cần chiều cao dòng ổn định hoặc đo động.
  • Ô tìm kiếm: debounce ~300ms và huỷ request cũ bằng AbortController. Giữ dữ liệu trang trước trong lúc chờ để bảng không nhấp nháy.
  • Đẩy page/sort/filter lên URL query: F5, share link, nút back đều giữ nguyên trạng thái. Đây là thứ hay bị quên nhất và rất dễ ghi điểm.
  • Chọn qua nhiều trang: giữ Set id đã chọn, thêm cờ “chọn tất cả theo filter” rồi gửi điều kiện filter cho server thay vì 10.000 id. Export lớn thì đẩy sang job nền.
const [sp] = useSearchParams();        // ✅ state bảng nằm trên URL
const q = { page: +(sp.get('page') ?? 1), sort: sp.get('sort') ?? 'id',
            search: sp.get('q') ?? '' };

const { data } = useQuery({
  queryKey: ['rows', q],
  queryFn: ({ signal }) => api.rows(q, { signal }),  // ✅ huỷ request cũ
  placeholderData: keepPreviousData,   // v5 — không nhấp nháy khi đổi
});

// ❌ tải hết 10.000 dòng rồi sort ở client → chặn main thread
// ✅ chọn nhiều trang: giữ id, "chọn tất cả" thì gửi filter cho server
const [picked] = useState<Set<string>>(new Set());
const payload = allMatching ? { filter: q } : { ids: [...picked] };
⚠ Bẫy phỏng vấn: Debounce nhưng quên huỷ request cũ: gõ “abc” bắn 3 request, response của “ab” về sau “abc” → bảng hiển thị kết quả không khớp ô tìm kiếm. Phải huỷ bằng AbortController hoặc bỏ qua response có query key cũ.
💬 Nói thêm để ghi điểm: Sort ở server phải ổn định: thêm id làm tie-breaker, không thì hai bản ghi cùng giá trị sẽ nhảy qua lại và item bị trùng hoặc mất giữa các trang. Virtualization cũng phá Ctrl+F và bản in — cần đường export.
