?Virtual DOM hoạt động thế nào?
?Vì sao không nên dùng index làm key?
💡 Trả lời
  • VDOM là cây object mô tả UI. Mỗi lần render dựng cây mới, React diff với cây cũ rồi chỉ vá đúng phần khác vào DOM thật.
  • Thuật toán diff dựa trên 2 giả định: khác type thẻ → huỷ cả cây con dựng lại; cùng cha thì dùng key để ghép node cũ với node mới.
  • key phải ổn định và duy nhất giữa các anh em ruột — lấy id từ dữ liệu, không lấy Math.random().
  • Dùng index: chèn/xoá/sắp xếp làm index lệch → React tái dùng nhầm node → state nội bộ (chữ trong input, focus, animation) dính sai hàng.
// ❌ thêm phần tử vào đầu danh sách → chữ trong input lệch hàng
{todos.map((t, i) => <TodoRow key={i} todo={t} />)}

// ✅ key gắn liền với dữ liệu, xáo trộn thế nào cũng đúng
{todos.map(t => <TodoRow key={t.id} todo={t} />)}
⚠ Bẫy phỏng vấn: Chỉ nói “index gây bug” là chưa đủ điểm. Phải chỉ rõ bug gì: React ghép nhầm node cũ với item mới nên state nội bộ và DOM node bị gán sai hàng.
💬 Nói thêm để ghi điểm: Nêu ngoại lệ để thể hiện hiểu sâu: index chấp nhận được khi danh sách tĩnh, không thêm/xoá/sắp xếp, và item không giữ state riêng.
