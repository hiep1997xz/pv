Volume · Bind mount · Dữ liệu
?Dữ liệu đi đâu khi bạn xoá container?
?Named volume khác bind mount chỗ nào?
💡 Trả lời
  • Layer ghi của container là tạm. Xoá container là mất. Mọi thứ cần sống lâu hơn container phải nằm ngoài nó.
  • Named volume do Docker quản lý, nằm ở khu vực riêng, sao lưu và di chuyển dễ. Đây là lựa chọn cho database ở mọi môi trường.
  • Bind mount trỏ thẳng vào thư mục máy thật — dùng cho dev để sửa code thấy ngay. Không nên dùng ở production vì phụ thuộc cấu trúc thư mục máy chủ.
  • tmpfs nằm trong RAM và mất khi container dừng — hợp cho file tạm và dữ liệu nhạy cảm không được chạm đĩa.
  • Bind mount hay vỡ vì quyền: tiến trình trong container chạy bằng UID khác chủ sở hữu thư mục trên host, thành ra permission denied.
# ✅ database: named volume, Docker tự quản lý
docker run -d -v pgdata:/var/lib/postgresql/data postgres:17

# ✅ dev: bind mount để sửa code là thấy ngay
docker run -v "$PWD/src:/app/src" -p 3000:3000 myapp

# ❌ bind mount đè mất node_modules đã cài trong image
docker run -v "$PWD:/app" myapp
# ✅ chừa node_modules ra bằng một volume ẩn danh
docker run -v "$PWD:/app" -v /app/node_modules myapp

# sao lưu volume ra file tar
docker run --rm -v pgdata:/d -v "$PWD:/b" alpine \
  tar czf /b/backup.tgz -C /d .
⚠ Bẫy phỏng vấn: Bind mount cả thư mục dự án vào /app sẽ đè lên node_modules đã cài trong image — container chạy lên báo thiếu module dù Dockerfile cài rồi. Chữa bằng cách chừa thư mục đó ra bằng volume ẩn danh.
💬 Nói thêm để ghi điểm: Nêu được thứ tự chọn: named volume cho dữ liệu thật, bind mount chỉ cho dev, tmpfs cho thứ không được chạm đĩa. Và volume không mất khi docker rm — phải docker volume rm mới xoá.
