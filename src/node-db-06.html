Cache Redis ở mức code
?Cache-aside viết trong Node thế nào cho đúng?
?Sửa dữ liệu rồi mà user vẫn thấy bản cũ, vì sao?
💡 Trả lời
  • Cache-aside: GET key → trúng thì JSON.parse trả luôn; trượt thì query DB, SET kèm EX rồi trả. Redis chết thì bỏ qua cache, đi thẳng DB — đừng để lỗi Redis giết request.
  • Key luôn có namespace và version: app:v2:user:123:profile. Đổi cấu trúc dữ liệu thì tăng lên v3, toàn bộ key cũ thành rác rồi tự bị eviction — không phải đi xoá tay.
  • Luôn có TTL, và cộng thêm jitter ngẫu nhiên để một loạt key không hết hạn cùng một giây. Key không TTL là chỗ để dữ liệu sai nằm lại vĩnh viễn.
  • Ghi thì xoá key, đừng chỉ đợi TTL. Xoá (DEL) an toàn hơn ghi đè, vì hai request ghi song song có thể set nhầm thứ tự. Và phải xoá sau khi commit, không phải trước.
  • Khi không nên cache: dữ liệu đổi liên tục (TTL ngắn hơn khoảng cách hai lần đọc thì hit rate gần 0), hoặc query vốn đã 2ms — thêm Redis chỉ là thêm một round-trip mạng.
// ioredis — cache-aside + khoá chống stampede
const KEY = (id: string) => `app:v2:user:${id}`;  // namespace + version
async function getUser(id: string) {
  const hit = await redis.get(KEY(id));
  if (hit) return JSON.parse(hit);
  // ✅ SET NX: chỉ 1 request đi DB, số còn lại chờ rồi đọc lại cache
  const ok = await redis.set(`lock:${KEY(id)}`, '1', 'EX', 5, 'NX');
  if (!ok) { await sleep(50); return getUser(id); }

  const u = await db.user.findUnique({ where: { id } });
  const ttl = 300 + Math.floor(Math.random() * 60);  // jitter chống dồn
  await redis.set(KEY(id), JSON.stringify(u), 'EX', ttl);
  return u;
}
// ✅ ghi xong thì XOÁ key, và phải xoá SAU khi commit transaction
⚠ Bẫy phỏng vấn: Xoá cache trước khi commit là bẫy tinh vi: giữa lúc xoá và lúc commit, một request khác đọc DB thấy giá trị cũ rồi nạp ngược vào cache. Dữ liệu sai nằm đó tới hết TTL mà không ai hiểu vì sao.
💬 Nói thêm để ghi điểm: Đo hit rate trước khi quyết định giữ cache — hit rate thấp thì cache chỉ cộng thêm độ trễ và thêm một chỗ để dữ liệu sai lệch. Redis cũng phải có maxmemory và policy allkeys-lru, nếu không sẽ OOM.
