Quản lý state · Context · Server state
?Khi nào cần Redux / Zustand?
?Context có thay được state manager không?
💡 Trả lời
  • Chia rõ 2 loại: server state (dữ liệu từ API — cần cache, refetch, đồng bộ) và client state (UI: modal, tab, form).
  • Server state → React Query / SWR. Tự lo cache, dedupe request, stale-while-revalidate, retry. Nhét vào Redux là tự viết lại một cái cache tệ hơn.
  • Client state: đơn giản thì useState + lifting up; phức tạp/chia sẻ rộng thì Zustand, Jotai, Redux Toolkit.
  • Context KHÔNG phải state manager — nó chỉ là đường truyền dữ liệu chống prop drilling. Mọi consumer re-render khi value đổi, và không có selector.
  • Context hợp với giá trị ít thay đổi: theme, ngôn ngữ, user đã đăng nhập.
// ❌ gom state đổi liên tục vào 1 Context → cả cây re-render
<AppContext.Provider value={{ user, cart, theme, mousePos }}>

// ✅ tách Context theo tần suất thay đổi
<ThemeContext.Provider value={theme}>
  <UserContext.Provider value={user}>
⚠ Bẫy phỏng vấn: Trả lời “dự án lớn thì dùng Redux” là mất điểm ngay. Người phỏng vấn muốn nghe bạn phân biệt được server state và client state.
