?Vì sao điều kiện “khác giá trị” lại bỏ sót dòng NULL?
💡 Trả lời
  • NULL nghĩa là không biết, không phải 0 cũng không phải chuỗi rỗng. Mọi so sánh với NULL (=, <>, >) đều cho ra NULL, mà WHERE chỉ giữ dòng ra true.
  • Nên status <> 'paid' bỏ sót sạch các dòng status IS NULL. Muốn lấy đủ thì viết IS DISTINCT FROM, hoặc thêm OR status IS NULL.
  • Kiểm tra NULL chỉ có một cách: IS NULL / IS NOT NULL. Viết = NULL không báo lỗi, chỉ lặng lẽ không khớp dòng nào.
  • COALESCE(a, b) trả giá trị non-NULL đầu tiên — dùng để hiển thị giá trị thay thế, không phải để che chỗ dữ liệu bị thiếu.
  • ORDER BY chạy xong mới tới LIMIT/OFFSET. Không có ORDER BY thì thứ tự dòng không đảm bảo; luôn thêm cột tie-break như id để phân trang không lặp dòng.
-- ❌ mất sạch dòng email IS NULL, mà không báo lỗi gì
SELECT id, name FROM users WHERE email <> 'an@ex.com';

-- ✅ cách 1: nói rõ là muốn lấy cả dòng NULL
SELECT id, name FROM users
WHERE email IS DISTINCT FROM 'an@ex.com';

-- ✅ cách 2: không lọc mất dòng, chỉ đổi cách hiển thị
SELECT id, COALESCE(email, '(chưa có)') AS email
FROM users
ORDER BY name, id        -- id là tie-break, phân trang mới ổn định
LIMIT 20 OFFSET 0;
⚠ Bẫy phỏng vấn: Đếm dòng status <> 'paid' rồi cộng với số dòng = 'paid' — tổng lại nhỏ hơn COUNT(*). Phần hụt chính là các dòng NULL. SQL không báo lỗi, báo cáo cứ thế sai.
💬 Nói thêm để ghi điểm: IS DISTINCT FROM coi hai NULL là bằng nhau, rất hợp khi viết điều kiện so dữ liệu cũ với dữ liệu mới. MySQL không có cú pháp này, thay bằng toán tử <=>.
