Form phức tạp · Validate · Autosave
?Form 50 trường: controlled hay uncontrolled?
?Lỗi validate từ server map vào field thế nào?
💡 Trả lời
  • Controlled: mỗi phím gõ là một lần set state → re-render cả form. Uncontrolled (react-hook-form register) giữ giá trị trong ref, chỉ render lại field có lỗi.
  • Validate theo schema (zod) thay vì rải rác if: một nguồn sự thật, suy ra được kiểu TypeScript bằng z.infer, và dùng lại được ở server.
  • Field lồng nhau và mảng động: tên field dạng items.0.qty, thêm/xoá dòng bằng useFieldArray. Key của dòng phải là id riêng, không phải index.
  • Autosave: debounce 500–1000ms, chỉ gửi khi form dirty và đã hợp lệ, kèm version của bản ghi để server từ chối khi có người khác sửa trước.
  • Chặn rời trang: beforeunload cho tab/refresh, blocker của router cho điều hướng trong app. Hai cái này không thay thế nhau.
const schema = z.object({
  email: z.string().email(),
  items: z.array(z.object({ qty: z.number().int().min(1) })).min(1),
});
type Form = z.infer<typeof schema>;
// ✅ uncontrolled: gõ phím không re-render cả form 50 trường
const { register, setError, handleSubmit } = useForm<Form>({
  resolver: zodResolver(schema),
});
async function onSubmit(v: Form) {
  const r = await api.save(v);          // 422 = lỗi nghiệp vụ từ server
  // ✅ map lỗi về đúng field thay vì toast chung chung
  r.errors?.forEach((e) =>
    setError(e.field as keyof Form, { message: e.msg }));
}
⚠ Bẫy phỏng vấn: Autosave debounce mà không huỷ request cũ: gõ nhanh rồi dừng, hai bản lưu chạy song song, bản cũ về sau đè lên bản mới. Cần AbortController hoặc version/updatedAt để server chặn ghi đè.
💬 Nói thêm để ghi điểm: Validate ở client chỉ là UX, server vẫn phải validate lại — dùng chung đúng một schema zod cho cả hai phía là điểm cộng lớn. Lỗi trả về nên có field + message theo chuẩn để map thẳng.
