CLI hằng ngày · Gỡ rối nhanh
?Container chết ngay khi khởi động, bạn làm gì?
?stop khác kill và rm thế nào?
💡 Trả lời
  • Việc đầu tiên luôn là docker logs --tail 100 -f. Đừng đoán khi log đang nằm sẵn ở đó.
  • docker ps chỉ thấy container đang chạy — phải docker ps -a mới thấy cái đã chết, kèm exit code ở cột STATUS.
  • docker exec chỉ vào được container đang chạy. Container chết ngay thì soi image bằng docker run --rm -it <image> sh.
  • stop gửi SIGTERM rồi chờ 10 giây mới SIGKILL. kill bắn SIGKILL ngay. rm xoá container đã dừng.
  • docker inspect xem cấu hình thật đang chạy (mount, network, env), docker stats xem CPU/RAM theo thời gian thực.
docker logs --tail 100 -f web    # ✅ xem lỗi trước tiên
docker ps -a                     # thấy cả container đã chết
docker inspect web | less        # mount, network, env thật

# chui vào container đang chạy
docker exec -it web sh

# container chết ngay → mở shell tạm trên chính image đó
docker run --rm -it node:22-alpine sh

docker system df                 # đĩa đang bị gì chiếm
docker system prune -a --volumes # ❌ xoá cả volume, mất data
⚠ Bẫy phỏng vấn: docker system prune -a kèm --volumes xoá luôn volume — tức là mất sạch dữ liệu database trên máy dev. Rất nhiều người chạy lệnh này cho nhẹ đĩa rồi mới phát hiện mất data.
💬 Nói thêm để ghi điểm: Đọc được exit code: 137 là bị SIGKILL, thường do hết RAM. Xác nhận bằng .State.OOMKilled trong docker inspect. 139 là segfault, 1 là app tự thoát vì lỗi.
