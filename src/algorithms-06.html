Sorting · Binary search
?[10, 9, 1].sort() trả về gì?
?Binary search cần điều kiện gì mới dùng được?
💡 Trả lời
  • Array.prototype.sort là O(n log n). V8 cài bằng TimSort: ổn định (stable) và rất nhanh với dữ liệu đã gần sắp xếp.
  • Nhớ nhanh: merge sort O(n log n) mọi trường hợp, tốn O(n) bộ nhớ, stable · quicksort trung bình O(n log n) nhưng xấu nhất O(n²) · bubble/insertion O(n²).
  • Binary search chỉ đúng khi dữ liệu đã sắp xếp, hoặc rộng hơn là khi điều kiện có tính đơn điệu. Mỗi bước loại một nửa → O(log n), O(1) bộ nhớ nếu viết bằng vòng lặp.
  • Hai biến thể phải nhớ: lower bound = vị trí đầu tiên có giá trị ≥ x, upper bound = vị trí đầu tiên > x. Hiệu hai cái chính là số lần x xuất hiện.
  • Chỉ tìm một phần tử trong mảng chưa sắp xếp thì quét thẳng O(n) nhanh hơn là sort O(n log n) rồi mới binary search.
// ❌ sort mặc định đổi phần tử sang CHUỖI rồi mới so sánh
console.log([10, 9, 1].sort());                // [ 1, 10, 9 ]
// ✅ với số phải truyền comparator
console.log([10, 9, 1].sort((a, b) => a - b)); // [ 1, 9, 10 ]

// Binary search tìm BIÊN TRÁI (vị trí đầu tiên >= x) — O(log n), O(1)
function lowerBound(a, x) {
  let lo = 0, hi = a.length;                   // hi là biên mở
  while (lo < hi) {
    const mid = (lo + hi) >> 1;
    if (a[mid] < x) lo = mid + 1; else hi = mid;
  }
  return lo;
}
console.log(lowerBound([1, 2, 2, 2, 5], 2));   // 1
⚠ Bẫy phỏng vấn: Bẫy số một của JS: [10, 9, 1].sort() ra [1, 10, 9], vì mặc định sort đổi phần tử sang chuỗi rồi so theo UTF-16 — "10" đứng trước "9". Với số luôn phải truyền (a, b) => a - b.
