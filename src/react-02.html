useState & cơ chế re-render
?Gọi setCount(count + 1) ba lần, kết quả tăng mấy?
?setState là đồng bộ hay bất đồng bộ?
💡 Trả lời
  • Hàm set không gán ngay, nó lên lịch render mới. Biến count là ảnh chụp (snapshot) của lần render hiện tại — đã bị “đóng băng”.
  • Automatic batching: nhiều lần set trong cùng một sự kiện gộp lại thành một lần render. React 18 gộp cả trong setTimeout/promise, React 17 thì không.
  • Cần dựa trên giá trị mới nhất → dùng updater function: setCount(c => c+1).
  • State phải immutable: tạo object/array mới. push, splice, gán obj.x=1 đều không kích hoạt render.
const [count, setCount] = useState(0);

// ❌ cả 3 dòng đều đọc count = 0  →  kết quả: 1
setCount(count + 1);
setCount(count + 1);
setCount(count + 1);

// ✅ mỗi lần nhận giá trị mới nhất  →  kết quả: 3
setCount(c => c + 1);
setCount(c => c + 1);
setCount(c => c + 1);
⚠ Bẫy phỏng vấn: Bẫy kinh điển: console.log(count) ngay sau setCount in ra gì? → Vẫn giá trị cũ, vì biến đó thuộc về lần render hiện tại chứ không phải lần render kế tiếp.
💬 Nói thêm để ghi điểm: Về immutable: setItems([...items, x]) thay vì items.push(x) — React so sánh bằng tham chiếu Object.is, mảng cũ thì coi như không đổi.
