💡 Trả lời
  • CommonJS: require đồng bộ, nạp lúc chạy, module.exports là object sửa được. ESM: import tĩnh, phân tích lúc parse, binding là live và chỉ đọc.
  • Node chọn loại theo đuôi file và "type" trong package.json: .mjs luôn ESM, .cjs luôn CommonJS, .js thì theo "type": "module" có hay không.
  • ESM import được CommonJS; chiều ngược lại phải dùng await import(). Trong ESM không có __dirname — thay bằng import.meta.dirname.
  • Trường "exports" khai báo điểm vào công khai của package và chặn import sâu vào file nội bộ, nhờ vậy đổi cấu trúc thư mục không làm vỡ người dùng.
  • Đọc env một lần lúc khởi động, validate rồi Object.freeze. Thiếu biến thì thoát ngay (fail fast) — thà chết lúc deploy còn hơn 500 lúc 2 giờ sáng.
// package.json: { "type": "module", "exports": "./src/index.js" }
const need = ['DATABASE_URL', 'JWT_SECRET'];
const missing = need.filter((k) => !process.env[k]);

if (missing.length) {
  console.error('Thiếu biến môi trường: ' + missing.join(', '));
  process.exit(1);        // ✅ fail fast, chết ngay lúc khởi động
}

export const config = Object.freeze({
  port: Number(process.env.PORT ?? 3000),
  dbUrl: process.env.DATABASE_URL,
  isProd: process.env.NODE_ENV === 'production',
});
// ❌ rải process.env khắp code → thiếu biến, vào nhánh đó mới nổ
⚠ Bẫy phỏng vấn: File .env chỉ dành cho máy local và không bao giờ commit; production dùng secret của nền tảng. Hỏi vặn hay gặp: “lỡ commit rồi thì sao?” → xoá khỏi repo là chưa đủ, phải rotate toàn bộ key đã lộ.
