Transaction · Bẫy quên await
?Trừ kho xong thì tạo đơn lỗi, dữ liệu sẽ ra sao?
?Vì sao transaction commit mà vẫn thiếu bản ghi?
💡 Trả lời
  • Nhiều thao tác phải cùng thành hoặc cùng huỷ thì bọc vào một transaction. Với pg: BEGIN / COMMIT / ROLLBACK phải chạy trên cùng một client, không phải trên pool.
  • Prisma: prisma.$transaction(...) nhận callback — throw bên trong thì tự ROLLBACK, chạy hết thì tự COMMIT. Không cần bắt lỗi rồi rollback bằng tay.
  • Phải truyền tx xuyên qua các tầng service. Hàm con vẫn gọi prisma toàn cục là nó chạy ngoài transaction — rollback không đụng tới nó. Cho tx vào tham số của mọi repository.
  • Bẫy quên await: gọi hàm async trong callback mà không await → callback kết thúc sớm, Prisma commit trước khi thao tác đó chạy xong, và lỗi văng ra thành unhandled rejection.
  • Transaction không được ôm lời gọi API bên ngoài (thanh toán, gửi mail). Bên kia chậm 5 giây là giữ lock 5 giây, giam một connection. Gọi trước, hoặc đẩy qua queue sau commit.
// Prisma: throw trong callback → tự ROLLBACK cả cụm
await prisma.$transaction(async (tx) => {
  const it = await tx.item.update({
    where: { id },
    data: { stock: { decrement: qty } },
  });
  if (it.stock < 0) throw new Error('hết hàng');  // rollback tất cả

  // ❌ quên await → transaction commit xong order mới chạy
  tx.order.create({ data: { itemId: id, qty } });

  // ✅ có await → lỗi ở đây mới kéo được cả cụm rollback
  await tx.order.create({ data: { itemId: id, qty } });
});
// ✅ gọi API thanh toán SAU commit, đừng để bên trong transaction
⚠ Bẫy phỏng vấn: Quên một chữ await trong $transaction là lỗi tàn nhẫn nhất: test vẫn pass, log không báo gì, chỉ thỉnh thoảng thiếu bản ghi con trên production. Bật rule no-floating-promises của typescript-eslint cho máy bắt hộ.
💬 Nói thêm để ghi điểm: Về isolation level: Postgres mặc định là Read Committed. Bài toán đọc-rồi-ghi cần Serializable hoặc SELECT ... FOR UPDATE. Và transaction nào cũng nên có timeout — giữ lock lâu là khoá cả bảng.
