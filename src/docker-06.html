Docker MIDDLE 06 / 08
Networking · DNS nội bộ
?Trong container, localhost trỏ vào đâu?
?Hai container gọi được nhau bằng cách nào?
💡 Trả lời
  • Mỗi container có network namespace riêng, nên localhost bên trong là chính container đó — không phải máy host, càng không phải container khác.
  • Cùng một user-defined network, container gọi nhau bằng tên nhờ DNS nội bộ của Docker. Viết db:5432 chứ không phải localhost:5432.
  • Network bridge mặc định không có DNS theo tên. Compose tự tạo network riêng nên trong Compose gọi tên service là chạy được ngay.
  • -p 8080:80 là host:container. Còn EXPOSE trong Dockerfile chỉ là ghi chú, tự nó không mở cổng nào cả.
  • Cần gọi ngược về máy host thì dùng host.docker.internal. Trên Linux phải thêm --add-host trỏ tới host-gateway.
docker network create app-net
docker run -d --name db  --network app-net postgres:17
docker run -d --name api --network app-net myapi

# ✅ trong container api, kết nối bằng TÊN container
#    DATABASE_URL=postgres://user:pass@db:5432/mydb

# ❌ localhost trong api là chính api, không phải db
#    DATABASE_URL=postgres://user:pass@localhost:5432/mydb

docker run -p 8080:80 nginx      # host 8080 → container 80
docker network inspect app-net   # ai đang trong network này
⚠ Bẫy phỏng vấn: Lỗi kinh điển khi đưa app lên Docker: giữ nguyên localhost trong connection string. Chạy ở máy thì được, vào container là connection refused, vì localhost giờ là chính container chứ không còn là máy bạn.
💬 Nói thêm để ghi điểm: Nói thêm ở mức production: đặt database vào network internal: true để nó không ra được internet, chỉ app trong cùng network gọi vào được. Và đừng -p cổng database ra host.
