💡 Trả lời
  • 1-1 mặc định gộp chung một bảng; chỉ tách khi cột hiếm dùng, nặng, hoặc khác vòng đời quyền truy cập — và bảng tách phải có UNIQUE trên cột FK, nếu không nó thành 1-n.
  • 1-n: FK nằm ở bảng "nhiều". Đừng nhét mảng id vào bảng "một" — mảng thì không có FK, không ràng buộc được, và join ra rất xấu.
  • n-n: bảng nối với PK tổ hợp (post_id, tag_id). Bảng nối gần như luôn mọc thêm cột riêng (role, added_at), nên coi nó là một thực thể thật ngay từ đầu.
  • Soft delete (deleted_at) có hai cái giá: mọi query phải nhớ lọc IS NULL, quên một chỗ là dữ liệu đã xoá hiện lại; và UNIQUE phải đổi thành partial index.
  • Cột audit created_at / updated_at đặt DEFAULT now() ở DB. updated_at nên do trigger cập nhật — đừng tin mọi đường ghi đều nhớ set nó.
CREATE TABLE post_tags (
  post_id  bigint NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  tag_id   bigint NOT NULL REFERENCES tags(id),
  added_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (post_id, tag_id)
);

// ❌ soft delete làm UNIQUE hỏng: user cũ không đăng ký lại được
CREATE UNIQUE INDEX users_email ON users (email);

// ✅ partial index: chỉ ép duy nhất trên các dòng còn sống
CREATE UNIQUE INDEX users_email_live
  ON users (email) WHERE deleted_at IS NULL;
⚠ Bẫy phỏng vấn: Quên WHERE deleted_at IS NULL ở một query báo cáo hay một endpoint mới là dữ liệu đã xoá quay lại màn hình khách hàng. Đây là loại bug không test nào bắt được, vì code vẫn chạy đúng — chỉ là trả thừa dòng.
