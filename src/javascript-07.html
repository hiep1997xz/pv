Event loop · macrotask · microtask
?setTimeout(fn, 0) có chạy ngay lập tức không?
?Thứ tự in của setTimeout và Promise.then là gì?
💡 Trả lời
  • JS chạy một luồng với một call stack. Việc bất đồng bộ do host (browser / Node) lo; xong thì callback được xếp vào queue chứ không chen ngang stack đang chạy.
  • Vòng lặp: chạy hết call stack → vét sạch microtask queue → (browser) render một frame → lấy đúng một macrotask chạy → quay lại vét microtask.
  • Microtask: .then/.catch/.finally, phần sau await, queueMicrotask, MutationObserver. Macrotask: setTimeout, setInterval, I/O, event handler.
  • Microtask luôn chạy trước macrotask kế tiếp. Microtask sinh ra microtask mới phải chạy hết trong cùng lượt vét — đệ quy microtask sẽ treo tab, đệ quy setTimeout thì không.
  • setTimeout(fn, 0) nghĩa là "xếp hàng sớm nhất có thể", không phải "chạy ngay": phải đợi stack rỗng và đợi microtask xong. Browser còn kẹp tối thiểu 4ms khi lồng quá 5 tầng.
console.log('1');
setTimeout(() => console.log('2'), 0);            // macrotask
Promise.resolve().then(() => console.log('3'));   // microtask
queueMicrotask(() => console.log('4'));           // microtask

(async () => {
  console.log('5');     // thân async chạy ĐỒNG BỘ tới await đầu tiên
  await null;
  console.log('6');     // phần sau await = microtask
})();

console.log('7');

// ✅ Thứ tự in thật:  1  5  7  3  4  6  2
// ❌ Đáp án sai hay gặp: 1 5 7 2 3 4 6 (tưởng timeout 0 chạy trước)
⚠ Bẫy phỏng vấn: Rất nhiều người nói await làm cả hàm thành bất đồng bộ từ dòng đầu. Sai — thân hàm async chạy đồng bộ tới await đầu tiên, phần còn lại mới thành microtask. Và async không tạo thread mới.
