TypeScript MIDDLE 04 / 08
Utility types dùng thật trong dự án
?Partial, Pick, Omit khác nhau chỗ nào?
?ReturnType lấy được kiểu trả về bằng cách nào?
💡 Trả lời
  • Nhóm sửa field: Partial<T> cho mọi field optional, Required<T> ngược lại, Readonly<T> khoá ghi. Dùng nhiều nhất là Partial cho payload update.
  • Nhóm chọn field: Pick<T, K> giữ những field liệt kê, Omit<T, K> bỏ chúng đi. Hay dùng để dựng type cho props UI từ type model.
  • Record<K, V> dựng object có key cố định, ví dụ Record<Role, Perm> — thêm role mới mà quên khai là TS báo lỗi ngay.
  • Nhóm lọc union: Exclude<T, U> bỏ nhánh khớp U, Extract<T, U> giữ nhánh khớp, NonNullable<T> bỏ null và undefined.
  • Nhóm rút kiểu từ hàm: ReturnType<typeof f>, Parameters<typeof f>, Awaited<T> mở Promise. Rất hợp để type hoá kết quả API mà khỏi khai lại.
type User = { id: string; name: string; email: string; age: number };

type UserPatch = Partial<Omit<User, 'id'>>;  // payload update
type UserCard = Pick<User, 'id' | 'name'>;   // props cho UI

type Role = 'admin' | 'editor' | 'viewer';
const perms: Record<Role, string[]> = {
  admin: ['*'], editor: ['write'], viewer: ['read'],  // thiếu 1 → lỗi
};

async function getUser(id: string) { return { id, name: 'a' }; }
type Fetched = Awaited<ReturnType<typeof getUser>>;

type Oops = Omit<User, 'emial'>;   // ❌ gõ sai key vẫn compile trót lọt
type Nope = Pick<User, 'emial'>;   // ✅ Pick gạch đỏ ngay: TS2344
⚠ Bẫy phỏng vấn: Omit có lỗ hổng: key truyền vào không bị ràng buộc theo keyof T, nên gõ sai tên field vẫn compile trót lọt và type ra thừa field. Pick thì báo TS2344. Đổi tên field xong nhớ rà lại mọi chỗ Omit.
💬 Nói thêm để ghi điểm: Partial chỉ nông một tầng, object lồng bên trong vẫn bắt buộc đủ field. Cần sâu thì tự viết mapped type đệ quy — đừng tưởng Partial lo hết cho mình.
