this · call/apply/bind · arrow
?Xác định this trong một hàm dựa vào cái gì?
?Vì sao truyền method làm callback thì mất this?
💡 Trả lời
  • this xác định lúc gọi, không phải lúc khai báo. 4 quy tắc ưu tiên giảm dần: new → call/apply/bind → gọi qua object o.f() → gọi trơn.
  • Gọi trơn: strict mode cho this = undefined, sloppy mode cho globalThis. Class body và ES module luôn strict, nên lỗi thường hiện ra dưới dạng TypeError.
  • Arrow không có this riêng — nó lấy this của scope bao ngoài lúc định nghĩa. Vì thế call/bind không đổi được this của arrow.
  • Tách o.f ra biến, hay truyền vào setTimeout/addEventListener, là mất luôn object gọi. Sửa bằng f.bind(o) hoặc bọc arrow () => o.f().
  • call(o, a, b) gọi ngay với danh sách tham số, apply(o, [a, b]) gọi ngay với mảng, bind(o) không gọi mà trả về hàm mới đã khoá this.
class Counter {
  n = 0;
  incBad() { this.n++; }          // method nằm trên prototype
  incOk = () => { this.n++; };    // class field arrow: this khoá vào c
}
const c = new Counter();
const bad = c.incBad, ok = c.incOk;

// ❌ tách khỏi object → this = undefined (class luôn strict)
try { bad(); } catch (e) { console.log(e.name); }   // TypeError

ok();                       // ✅ arrow giữ nguyên this
c.incBad.call(c);           // ✅ ép this bằng call
setTimeout(c.incBad.bind(c), 0);   // ✅ bind trả về hàm mới
console.log(c.n);           // 2 — sau timeout thành 3
⚠ Bẫy phỏng vấn: Rất khó tìm: cùng một lỗi mất this mà hai nơi biểu hiện khác nhau. Trong class (strict) nó ném TypeError ngay; trong hàm thường sloppy mode this thành globalThis nên code âm thầm ghi biến toàn cục.
💬 Nói thêm để ghi điểm: Arrow không chỉ thiếu this: nó cũng không có arguments, không có prototype, không gọi được bằng new, và không làm generator được. Kể đủ danh sách này là điểm cộng rõ.
