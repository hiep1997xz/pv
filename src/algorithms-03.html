Hash map · đếm tần suất & nhóm
?Giải two-sum trong O(n) như thế nào?
?Khi nào nên dùng Map thay cho Object thường?
💡 Trả lời
  • Hash map đổi bộ nhớ lấy tốc độ: tốn thêm O(n) bộ nhớ để tra cứu O(1) trung bình, hạ rất nhiều bài từ O(n²) xuống O(n).
  • Two-sum một lượt: vừa quét vừa lưu, mỗi phần tử hỏi “số bù target - x đã gặp chưa?”. Không cần sort nên index gốc được giữ nguyên.
  • Đếm tần suất: m.set(x, (m.get(x) ?? 0) + 1). Nhóm anagram: lấy chữ cái đã sắp xếp của từ làm key — eat, tea, ate cùng key aet.
  • Dùng Set khi chỉ cần biết “có hay không”, Map khi cần gắn kèm giá trị. Cả hai has/get/set đều O(1) trung bình.
  • Map hơn Object ở chỗ: key nhận mọi kiểu (không bị ép sang chuỗi), giữ đúng thứ tự chèn, có size, lặp trực tiếp được, và không dính key kế thừa.
// two-sum mảng CHƯA sắp xếp — O(n) thời gian, O(n) bộ nhớ
function twoSum(nums, target) {
  const seen = new Map();                  // giá trị -> index
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need), i];
    seen.set(nums[i], i);
  }
}
console.log(twoSum([2, 7, 11, 15], 9));    // [ 0, 1 ]

const o = {}; o[1] = 'số'; o['1'] = 'chuỗi';  // ❌ cùng MỘT key
console.log(o[1], Object.keys(o).length);     // chuỗi 1
const m = new Map([[1, 'số']]).set('1', 'chuỗi');
console.log(m.get(1), m.size);       // ✅ số 2 — Map tách thành 2 key
⚠ Bẫy phỏng vấn: Bẫy Object: o[1] và o["1"] là cùng một key vì key của object luôn bị ép sang chuỗi — đếm số 1 và chuỗi "1" sẽ gộp làm một. Thêm nữa "toString" in {} trả về true, dễ đếm nhầm.
