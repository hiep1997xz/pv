Monorepo · pnpm workspace · Turborepo
?Khi nào nên dùng monorepo, khi nào không?
?Turborepo giải quyết vấn đề gì mà workspace không làm được?
💡 Trả lời
  • Monorepo đáng dùng khi nhiều app dùng chung code và thay đổi cùng nhau: đổi một component design system là sửa luôn mọi nơi dùng nó, trong một PR duy nhất (atomic change).
  • pnpm workspace lo phần liên kết package nội bộ và chia sẻ node_modules. Chia thường thấy: apps/* cho ứng dụng, packages/ui, packages/config (eslint, tsconfig), packages/utils.
  • Turborepo (hoặc Nx) lo chạy task: khai báo pipeline phụ thuộc, chạy song song, cache theo hash input — không đổi thì không build lại. Remote cache dùng chung cho team và CI.
  • Mặt trái: CI dễ phình vì mỗi PR đụng nhiều package — phải lọc theo affected. Ranh giới sở hữu mờ đi, cần CODEOWNERS. Repo nặng dần, git thao tác chậm.
  • Đa repo tốt hơn khi các team có nhịp release độc lập, stack khác nhau, hoặc yêu cầu phân quyền truy cập nghiêm ngặt.
packages:                            # pnpm-workspace.yaml
  - "apps/*"
  - "packages/*"

// turbo.json — "^build" = build xong dependency rồi mới tới mình
{
  "tasks": {
    "build": { "dependsOn": ["^build"], "outputs": ["dist/**"] },
    "test":  { "dependsOn": ["build"] },
    "lint":  {}
  }
}

// ✅ chỉ chạy cho package đổi so với main → CI không phình
turbo run test --filter=...[origin/main]
⚠ Bẫy phỏng vấn: Câu trả lời trừ điểm: “công ty lớn nên dùng monorepo”. Monorepo là công cụ giải quyết chia sẻ code và thay đổi xuyên package, không phải chuẩn mực quy mô. Ba app không liên quan nhau nhét chung repo chỉ tạo CI chậm và conflict vô nghĩa.
