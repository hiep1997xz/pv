💡 Trả lời
  • next/image tự sinh srcset, lazy-load, và giữ chỗ theo width/height nên không gây CLS. Ảnh LCP phải đặt priority; dùng fill thì bắt buộc khai sizes.
  • next/font self-host font lúc build: không request sang Google, và tự sinh fallback có size-adjust nên chữ không nhảy khi font tải xong.
  • INP đã thay FID từ 2024, đo độ trễ phản hồi tương tác. Cách giảm: bớt JS phía client, next/dynamic cho phần nặng, đẩy logic về Server Component.
  • Soi bundle bằng @next/bundle-analyzer trước khi tối ưu. Thủ phạm quen mặt: import cả gói lodash, icon pack, thư viện chart nằm trong Client Component.
  • SEO: export const metadata cho trang tĩnh, generateMetadata() async cho tiêu đề theo dữ liệu. Thêm app/sitemap.ts, app/robots.ts để sinh file tự động.

// SEO động: tiêu đề theo từng bài viết
export async function generateMetadata({ params }) {
  const { slug } = await params;
  const post = await getPost(slug);   // cùng fetch với page → dedupe
  return { title: post.title, openGraph: { images: [post.cover] } };
}
⚠ Bẫy phỏng vấn: Hỏi vặn: "dùng next/image là hết CLS chứ?" → Không. Để fill mà container không có chiều cao xác định thì vẫn nhảy. Và priority chỉ dành cho ảnh trong viewport đầu — rải khắp nơi là tranh băng thông, LCP còn tệ hơn.
💬 Nói thêm để ghi điểm: generateMetadata chỉ chạy được trong Server Component. Nếu nó và page cùng gọi một fetch, request memoization gộp lại thành một lần — không cần truyền dữ liệu qua lại.
