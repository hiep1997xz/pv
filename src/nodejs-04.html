💡 Trả lời
  • Middleware là một chuỗi chạy đúng theo thứ tự app.use. Không gọi next() mà cũng không trả response thì request treo tới khi client timeout.
  • Parse body phải đăng ký trước route, error middleware phải đăng ký sau cùng. Đặt nhầm chỗ là req.body thành undefined, hoặc lỗi không ai bắt.
  • Validate ở biên bằng schema (zod, Valibot): từ handler trở vào coi như dữ liệu đã sạch và đúng kiểu. Luôn đặt limit cho body để chặn payload khổng lồ.
  • Status code: 400 body sai cú pháp · 401 chưa đăng nhập · 403 đã đăng nhập nhưng không đủ quyền · 404 không tồn tại · 409 xung đột · 422 đúng cú pháp nhưng sai nghiệp vụ.
  • CORS là cơ chế của trình duyệt nhưng phải sửa ở server bằng header. Liệt kê origin cụ thể; đã bật credentials thì không được để origin là *.
const app = express();
app.use(express.json({ limit: '100kb' }));  // ✅ parse body TRƯỚC route

const Body = z.object({
  email: z.string().email(),
  age: z.number().int().min(18),
});

app.post('/users', async (req, res) => {
  const p = Body.safeParse(req.body);
  if (!p.success) return res.status(400).json(p.error.issues);
  if (await exists(p.data.email)) return res.status(409).end();
  res.status(201).json(await create(p.data));
});
app.use(errorHandler);     // ✅ error middleware đăng ký SAU CÙNG
⚠ Bẫy phỏng vấn: Câu vặn hay gặp: “thêm cors() rồi mà trình duyệt vẫn chặn?” → thường là request preflight OPTIONS bị một route khác hoặc auth middleware nuốt trước, nên header CORS không kịp gắn vào response.
