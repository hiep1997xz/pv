Layout shift · z-index · overflow

?Đặt z-index 9999 rồi mà vẫn bị che, vì sao?
💡 Trả lời
  • Đo CLS: Lighthouse cho số trong phòng lab, thư viện web-vitals gửi số thật từ người dùng, còn Performance panel chỉ đúng phần tử nào đã dịch chuyển.
  • Dịch chuyển đến từ: ảnh và iframe không đặt width/height nên cao 0 rồi đột ngột giãn · font swap đổi metric chữ · banner chèn động phía trên nội dung.
  • Sửa: luôn khai kích thước hoặc aspect-ratio · next/font tự khớp metric chữ fallback · chừa sẵn chỗ bằng skeleton đúng kích thước thật, không phải skeleton cho có.
  • z-index chỉ so sánh được trong cùng một stacking context. Cha có transform, filter, opacity nhỏ hơn 1, hay position: fixed là tạo context mới — con nằm trọn trong đó.
  • overflow: hidden ở cha cắt cụt dropdown, tooltip; lồng nhiều vùng cuộn thì scroll bị kẹt. Gọn nhất: render qua createPortal ra body, định vị bằng Floating UI.
// ❌ ảnh không khai kích thước → nội dung nhảy khi ảnh tải xong
<img src="/banner.jpg" alt="" />

// ✅ chừa chỗ trước: next/image bắt buộc width/height hoặc fill
<Image src="/banner.jpg" alt="" width={1200} height={400} />

// ❌ .card tạo stacking context mới → tooltip 9999 vẫn bị che
// .card    { opacity: .99 }
// .tooltip { z-index: 9999 }
// .header  { position: sticky; z-index: 10 }

// ✅ đẩy tooltip ra ngoài cây, thoát cả stacking context lẫn overflow
createPortal(<Tooltip />, document.body);
⚠ Bẫy phỏng vấn: Hiểu nhầm kinh điển: tưởng z-index: 9999 thì luôn nổi lên trên. Nếu cha đã nằm trong một stacking context thấp hơn thì cả cây con bị nhốt trong đó, số to đến mấy cũng vô nghĩa. Mở tab Layers hoặc Computed để truy ra cha nào tạo context.
💬 Nói thêm để ghi điểm: Bẫy ngầm: overflow: hidden không chỉ cắt hình, nó còn biến phần tử thành scroll container và làm hỏng position: sticky của con. Gặp sticky "không chịu dính", đi ngược lên cha tìm overflow trước tiên.
