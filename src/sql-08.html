Window function · PARTITION BY
?ROW_NUMBER, RANK, DENSE_RANK khác nhau ra sao?
?Lấy bản ghi mới nhất của mỗi nhóm bằng cách nào?
💡 Trả lời
  • Window function tính trên một “cửa sổ” các dòng liên quan nhưng không gộp dòng lại — khác hẳn GROUP BY. Số dòng đầu ra đúng bằng số dòng đầu vào.
  • Khi giá trị bằng nhau (100, 100, 90, 80): ROW_NUMBER ra 1-2-3-4 (không bao giờ trùng) · RANK ra 1-1-3-4 (nhảy số) · DENSE_RANK ra 1-1-2-3 (không nhảy).
  • PARTITION BY chia dòng thành nhóm rồi đánh số lại từ đầu trong mỗi nhóm. ORDER BY nằm trong OVER() quyết định thứ tự đánh số, độc lập với ORDER BY của cả câu.
  • Lấy bản ghi mới nhất mỗi nhóm: ROW_NUMBER() với PARTITION BY user_id và ORDER BY created_at DESC, rồi lọc rn = 1 ở tầng ngoài.
  • Running total là SUM(x) OVER (ORDER BY id). Khung mặc định là RANGE nên các dòng bằng nhau ở cột ORDER BY bị cộng gộp chung một lượt — cần chính xác từng dòng thì ghi rõ ROWS.
-- điểm 100, 100, 90, 80 cho ra ba kiểu thứ hạng khác nhau:
-- ROW_NUMBER → 1 2 3 4 · RANK → 1 1 3 4 · DENSE_RANK → 1 1 2 3

-- ✅ lấy đơn hàng mới nhất của từng user
SELECT user_id, id, created_at FROM (
  SELECT o.*, ROW_NUMBER() OVER (
           PARTITION BY user_id ORDER BY created_at DESC) AS rn
  FROM orders o
) x WHERE rn = 1;

-- ❌ WHERE ROW_NUMBER() OVER (...) = 1  → lỗi, window chạy SAU WHERE

-- running total — ghi rõ ROWS để không cộng gộp dòng bằng nhau
SELECT id, SUM(amount) OVER (ORDER BY id ROWS UNBOUNDED PRECEDING)
FROM orders;
⚠ Bẫy phỏng vấn: Lọc ngay cùng tầng là hỏng cả hai đường: WHERE rn = 1 báo column "rn" does not exist, còn nhét thẳng hàm vào WHERE thì báo not allowed in WHERE. Window function chạy sau WHERE nên bắt buộc bọc thêm một tầng subquery hoặc CTE.
💬 Nói thêm để ghi điểm: PostgreSQL có DISTINCT ON (user_id) lấy dòng đầu của mỗi nhóm, ngắn hơn ROW_NUMBER nhiều; ghép với ORDER BY user_id, created_at DESC là ra bản ghi mới nhất. MySQL không có cú pháp này.
