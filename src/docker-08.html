?Vì sao không nên chạy container bằng root?
?Đưa secret vào container thế nào cho an toàn?
💡 Trả lời
  • Mặc định tiến trình trong container là root. Thoát được container là thành root trên host. Luôn tạo user thường và thêm USER trong Dockerfile.
  • Không đặt secret vào ENV hay ARG — chúng nằm lại trong docker history, ai đọc được image là đọc được. Mount file lúc chạy hoặc dùng secret của orchestrator.
  • Ghim base image theo digest chứ đừng dùng latest. latest hôm nay và tháng sau là hai image hoàn toàn khác nhau.
  • Siết quyền lúc chạy: --read-only, --cap-drop ALL rồi thêm lại đúng quyền cần, và đặt giới hạn --memory, --cpus.
  • Quét lỗ hổng ngay trong CI trước khi push: docker scout cves hoặc trivy image. Đừng để tới lúc đã lên production mới quét.
# --- Dockerfile ---
FROM node:22-alpine
RUN addgroup -S app && adduser -S app -G app
USER app                    # ✅ không chạy bằng root
HEALTHCHECK CMD wget -qO- localhost:3000/health || exit 1
CMD ["node", "dist/index.js"]

# ❌ secret nằm lại trong docker history, ai có image là đọc được
# ENV API_KEY=sk_live_abc123

# --- lúc chạy: siết quyền, mount secret dạng file ---
docker run --read-only --cap-drop ALL --memory 512m \
  -v app-secrets:/run/secrets:ro myapp

docker scout cves myapp     # quét trước khi push lên registry
⚠ Bẫy phỏng vấn: Đừng trả lời “container cô lập rồi thì chạy root cũng không sao”. Container dùng chung kernel với host — root trong container là root thật, chỉ đang bị namespace che. Thoát ra được là chiếm luôn máy chủ.
💬 Nói thêm để ghi điểm: Nêu được vấn đề PID 1: tiến trình chạy ở PID 1 không có handler mặc định cho SIGTERM, nên docker stop phải chờ hết 10 giây rồi mới giết. Tự bắt tín hiệu, hoặc chạy với --init.
