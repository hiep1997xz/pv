CORS · preflight · credentials
?Vì sao Postman gọi được mà trình duyệt báo lỗi CORS?
?Khi nào trình duyệt gửi preflight OPTIONS?
💡 Trả lời
  • Lỗi luôn có dạng blocked by CORS policy. Request vẫn tới server và server vẫn xử lý — trình duyệt chỉ chặn không cho JS đọc response.
  • Trình duyệt gửi preflight OPTIONS khi request không "đơn giản": method ngoài GET/POST/HEAD, có header tự đặt (vd Authorization), hoặc Content-Type: application/json.
  • Quyết định nằm ở header server trả về: Access-Control-Allow-Origin, -Allow-Methods, -Allow-Headers. Preflight trả 204 kèm Access-Control-Max-Age để trình duyệt cache lại.
  • Gửi cookie (credentials: "include") thì không được dùng * — phải ghi rõ đúng một origin và thêm Access-Control-Allow-Credentials: true. Dùng * là trình duyệt chặn thẳng.
  • CORS là cơ chế của trình duyệt. Postman, curl, server-to-server không kiểm tra nên vẫn chạy ngon — đừng lấy đó làm bằng chứng "API không lỗi".
// ❌ vô ích: đây là header của RESPONSE, client không tự cấp
fetch(url, { headers: { 'Access-Control-Allow-Origin': '*' } });

// ✅ sửa ở server — app/api/data/route.ts (Next.js)
const cors = {
  'Access-Control-Allow-Origin': 'https://app.example.com',
  'Access-Control-Allow-Credentials': 'true',
  'Access-Control-Allow-Headers': 'Content-Type, Authorization',
};
export async function GET() {
  return Response.json({ ok: true }, { headers: cors });
}
// ✅ preflight OPTIONS trả 204 kèm đúng bộ header trên
export const OPTIONS = () =>
  new Response(null, { status: 204, headers: cors });
⚠ Bẫy phỏng vấn: Hiểu nhầm số một: tưởng sửa được ở phía client. Thêm header vào request, đặt mode: "no-cors" hay tắt CORS bằng extension đều vô ích — no-cors trả response opaque, đọc body ra rỗng. Chỉ server hoặc proxy mới sửa được.
💬 Nói thêm để ghi điểm: Trong Next.js có đường vòng chính thống: gọi qua route handler ở app/api/*, hoặc khai rewrites trong next.config.js. Request đi từ server nên không dính CORS, lại giấu được API key.
