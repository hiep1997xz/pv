Hoisting · TDZ · scope
?var, let, const khác nhau ở những điểm nào?
?TDZ là gì và vì sao let lại có TDZ?
💡 Trả lời
  • Hoisting: engine quét scope lúc compile và cấp chỗ cho mọi khai báo trước khi chạy. var được gán sẵn undefined; let/const cũng hoisted nhưng chưa khởi tạo.
  • TDZ (temporal dead zone) là khoảng từ đầu block tới dòng khai báo. Chạm vào biến trong đó ném ReferenceError, khác hẳn việc nhận undefined.
  • var là function scope nên rò ra khỏi if/for; let/const là block scope. const chỉ cấm gán lại, không cấm sửa nội dung object.
  • Function declaration hoisted cả thân hàm nên gọi trước khi khai báo vẫn chạy. Function expression gán vào var thì gọi sớm sẽ báo is not a function.
  • Gán biến chưa khai báo (x = 1) tạo biến toàn cục ngầm ở sloppy mode. 'use strict' và ES module chặn việc này bằng ReferenceError.
console.log(typeof a);   // "undefined" — var hoisted, gán sẵn undefined
var a = 1;

sayHi();                 // ✅ chạy được: declaration hoisted cả thân hàm
function sayHi() { console.log('hi'); }

try { console.log(b); }  // ❌ ReferenceError: Cannot access 'b'
catch (e) { console.log(e.name); }
let b = 2;

if (true) { var v = 1; let l = 2; }
console.log(v);          // 1 — var rò ra ngoài block
console.log(typeof l);   // "undefined" — l chết theo block
⚠ Bẫy phỏng vấn: typeof x với biến chưa khai báo trả về "undefined", không ném lỗi. Nhưng nếu x khai báo bằng let ở dưới thì typeof x vẫn ném ReferenceError — ngoại lệ duy nhất của typeof.
💬 Nói thêm để ghi điểm: Nhấn rằng hoisting không phải "di chuyển code lên trên". Đó chỉ là hệ quả của việc engine tạo binding trước khi thực thi — var có giá trị khởi tạo, let thì chưa.
