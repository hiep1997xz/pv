TypeScript SENIOR 08 / 08
Conditional types · infer · khi nào quá đà
?Distributive conditional type nghĩa là gì?
?infer dùng để làm gì, cho một ví dụ?
💡 Trả lời
  • T extends U ? X : Y là if ở tầng type. Chữ extends ở đây nghĩa là “gán được vào”, không phải kế thừa class.
  • Distributive: khi T là naked type param và nhận vào một union, điều kiện chạy từng nhánh rồi hợp kết quả lại. Exclude hoạt động đúng nhờ vậy.
  • Muốn tắt distributive thì bọc tuple: [T] extends [U]. Dùng khi cần xét cả union như một khối, ví dụ kiểm tra một type có phải never không.
  • infer đặt một ô trống để TS điền type vào khi khớp mẫu — đây là cơ sở của ReturnType, Parameters và Awaited.
  • Khi nào là quá đà: type khó hiểu hơn code nó bảo vệ, thông báo lỗi dài mấy chục dòng, đồng đội không sửa nổi. Lúc đó khai type tường minh còn rẻ hơn nhiều.
// tự viết lại ReturnType
type MyReturn<T> = T extends (...a: any[]) => infer R ? R : never;
type A = MyReturn<() => string>;    // string

// tự viết lại Awaited (bản rút gọn, mở Promise lồng nhau)
type MyAwaited<T> = T extends Promise<infer U> ? MyAwaited<U> : T;
type B = MyAwaited<Promise<Promise<number>>>;   // number

// distributive: chạy từng nhánh của union rồi hợp lại
type NoStr<T> = T extends string ? never : T;
type C = NoStr<string | number | boolean>;      // number | boolean

// ❌ bọc tuple là tắt distributive → xét cả union một khối
type D = [string | number] extends [string] ? 1 : 0;   // 0
⚠ Bẫy phỏng vấn: Distributive cắn ngược: tự viết T extends null ? never : T rồi truyền never vào sẽ nhận lại never, vì union rỗng phân phối ra rỗng. Nhiều người tưởng đó là bug của TS thay vì đúng quy tắc.
💬 Nói thêm để ghi điểm: Nêu giới hạn thật: conditional type đệ quy có depth limit, vượt là TS bắn TS2589 — “Type instantiation is excessively deep and possibly infinite”. Gặp lỗi đó thì đơn giản hoá type, đừng lách bằng any.
