Custom hook & Design patterns
?Khi nào nên tách ra custom hook?
?Compound component giải quyết vấn đề gì?
💡 Trả lời
  • Custom hook tái sử dụng LOGIC có state, không tái sử dụng UI. Quy tắc: tên bắt đầu bằng use, và có gọi hook khác bên trong.
  • Mỗi component gọi hook nhận một state độc lập — hook không chia sẻ state giữa các component. Đây là chỗ hay bị hiểu nhầm nhất.
  • Compound component: cha giữ state, các con lấy qua Context → API dùng linh hoạt như <Tabs> + <Tabs.List/> + <Tabs.Panel/>.
  • Headless (Radix, Headless UI): tách hành vi + accessibility ra khỏi giao diện, người dùng tự style hoàn toàn.
  • HOC và render props là pattern thời trước hooks — cần biết để đọc code cũ và trả lời câu so sánh.
function useDebounce(value, delay = 300) {
  const [v, setV] = useState(value);

  useEffect(() => {
    const t = setTimeout(() => setV(value), delay);
    return () => clearTimeout(t);     // huỷ timer cũ mỗi lần gõ phím
  }, [value, delay]);

  return v;
}
⚠ Bẫy phỏng vấn: “Hai component cùng gọi useCounter() thì dùng chung số đếm chứ?” → KHÔNG. Mỗi lần gọi tạo một state riêng biệt.
