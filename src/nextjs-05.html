Route Handler · Server Actions
?Khi nào dùng Server Action, khi nào dùng Route Handler?
?Server Action có an toàn hơn API route không?
💡 Trả lời
  • Route Handler (app/api/*/route.ts) là HTTP endpoint thật: webhook, OAuth callback, client bên ngoài, CORS, custom method. Next 15 GET handler không cache mặc định.
  • Server Action (use server) là hàm chạy trên server, gọi thẳng từ component, luôn là POST. Hợp cho mutation nội bộ app, kèm revalidateTag và redirect.
  • Gắn vào form action={fn} thì form submit được cả khi JS chưa tải xong (progressive enhancement) — điểm mà Route Handler không có.
  • useFormStatus() (react-dom) đọc trạng thái pending của form cha; useActionState() (React 19) giữ giá trị action trả về để hiện lỗi validate.
  • Server Action được compile thành một endpoint công khai. Auth và validate input phải nằm trong thân hàm, không phải ở chỗ gọi nó.
'use server';
export async function updateName(prev, formData) {
  const user = await auth();      // ✅ check quyền NGAY trong action
  if (!user) return { error: 'Bạn chưa đăng nhập' };

  // ✅ validate ở server, không tin dữ liệu gửi lên
  const input = Schema.safeParse(Object.fromEntries(formData));
  if (!input.success) return { error: 'Tên không hợp lệ' };

  await db.user.update({ where: { id: user.id }, data: input.data });
  revalidatePath('/profile');
  return { ok: true };
}
// ❌ chỉ ẩn nút trên UI rồi tin là an toàn — endpoint vẫn gọi được
⚠ Bẫy phỏng vấn: Hỏi vặn: "Server Action chạy trên server thì khỏi validate chứ?" → Sai. Next sinh một endpoint POST cho mỗi action, ai cũng bắn request thẳng vào được. Ẩn nút, disable form hay check ở Client Component đều không tính là bảo mật.
💬 Nói thêm để ghi điểm: redirect() hoạt động bằng cách ném exception. Bọc nó trong try/catch là bị nuốt mất và redirect không chạy — luôn đặt redirect() sau khối try, khi mọi việc đã xong.
