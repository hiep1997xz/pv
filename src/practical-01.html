Thực Chiến JUNIOR 01 / 08
Infinite scroll · Virtualization
?Dùng IntersectionObserver hay sự kiện scroll?
?Vì sao phân trang bằng offset lại bị trùng item?
💡 Trả lời
  • IntersectionObserver theo dõi một sentinel ở cuối danh sách. Callback chạy ngoài luồng scroll nên không cần throttle và không gây layout thrashing như onScroll.
  • Cursor pagination: gửi con trỏ của item cuối (vd created_at + id) thay vì vị trí tuyệt đối. Dữ liệu mới chèn vào không làm lệch các trang sau.
  • Virtualization là chuyện khác: infinite scroll lo tải thêm, virtualization lo chỉ render phần nhìn thấy. Cần khi DOM node phình lên hàng nghìn hoặc mỗi dòng nặng.
  • Giữ vị trí cuộn: chỉ nối vào cuối mảng, key ổn định theo id. Chèn vào đầu hoặc thay cả mảng là trình duyệt nhảy cuộn.
  • Luôn có trạng thái đang tải, hết dữ liệu và lỗi + nút thử lại. Thiếu cờ hết dữ liệu là observer bắn request vô hạn.
// ❌ offset: có bài mới chèn lên đầu → trang 2 lặp lại item trang 1
api.feed({ offset: page * 20, limit: 20 });

// ✅ cursor: neo vào item cuối, dữ liệu mới không phá trang sau
const { data, fetchNextPage, hasNextPage } = useInfiniteQuery({
  queryKey: ['feed'],
  queryFn: ({ pageParam }) => api.feed({ cursor: pageParam, limit: 20 }),
  initialPageParam: null as string | null,
  getNextPageParam: (last) => last.nextCursor ?? undefined,
});

const io = new IntersectionObserver(([e]) => {
  if (e.isIntersecting && hasNextPage) fetchNextPage();
}, { rootMargin: '400px' });   // tải trước khi chạm đáy 400px
io.observe(sentinelRef.current!);
⚠ Bẫy phỏng vấn: Offset hỏng khi dữ liệu đổi giữa hai lần gọi: thêm 1 bài lên đầu thì item thứ 20 bị đẩy xuống 21 → trang 2 trả lại đúng item đó. Xoá 1 bài thì ngược lại, có item bị nhảy mất, không ai nhìn thấy.
💬 Nói thêm để ghi điểm: Cursor phải sắp xếp trên cột duy nhất và không đổi. Sắp theo created_at đơn thuần mà hai bản ghi trùng giây là lặp hoặc sót — ghép thêm id làm tie-breaker.
