Generic · ràng buộc extends · suy luận kiểu
?Generic giải quyết gì mà any không làm được?
?Khi nào một hàm KHÔNG cần generic?
💡 Trả lời
  • Generic giữ mối liên hệ giữa đầu vào và đầu ra. any làm mất type ở đầu ra; generic thì truyền number vào là nhận number ra.
  • TS tự suy luận type param từ đối số, hiếm khi phải viết tay. Chỉ viết rõ khi suy luận ra hẹp/rộng không như ý.
  • Ràng buộc bằng extends: <T extends { id: string }> cho phép dùng field trong thân hàm mà vẫn giữ nguyên type gốc của caller.
  • Default type param <T = string> để caller bỏ qua. Generic dùng được cả trong interface và class, như Map<K, V> hay Array<T>.
  • Không cần generic khi type param chỉ xuất hiện đúng một lần trong signature — lúc đó nó là any trá hình, thay bằng union hoặc kiểu cụ thể.
// ❌ any: nhận gì cũng được, trả về any — mất sạch type
function firstAny(arr: any[]): any { return arr[0]; }

// ✅ generic: type đầu ra bám theo đầu vào
function first<T>(arr: T[]): T | undefined { return arr[0]; }
const n = first([1, 2, 3]);       // n: number | undefined

// ràng buộc extends để đụng được field bên trong
function byId<T extends { id: string }>(list: T[], id: string) {
  return list.find(x => x.id === id);    // trả về T | undefined
}

// ❌ generic thừa: T chỉ xuất hiện một lần
function log<T>(x: T) { console.log(x); }
⚠ Bẫy phỏng vấn: arr[0] của T[] được TS coi là T chứ không phải T | undefined — mảng rỗng là nổ lúc runtime mà compiler vẫn im. Bật noUncheckedIndexedAccess mới có undefined trong type.
