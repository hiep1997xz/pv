Quy hoạch động · memoization
?Làm sao biết một bài nên giải bằng DP?
?Memoization và tabulation khác nhau ra sao?
💡 Trả lời
  • Nhận diện DP qua hai dấu hiệu: overlapping subproblems (một bài con bị tính lại nhiều lần) và optimal substructure (lời giải tối ưu ghép từ lời giải tối ưu của bài con).
  • Thiếu overlapping subproblems thì đó là divide and conquer (merge sort), không phải DP. Nếu chọn cục bộ luôn cho kết quả tối ưu thì dùng greedy, rẻ hơn nhiều.
  • Top-down (memoization): giữ nguyên đệ quy, thêm cache. Dễ viết, chỉ tính đúng những bài con thực sự cần, nhưng vẫn tốn call stack.
  • Bottom-up (tabulation): vòng lặp điền bảng từ base case đi lên. Không lo vỡ stack và thường nhanh hơn vì bỏ được chi phí gọi hàm.
  • Leo cầu thang chính là Fibonacci: đệ quy trần O(2^n), thêm memo còn O(n). Vì mỗi bước chỉ cần 2 giá trị liền trước, bỏ mảng dp đi là còn O(1) bộ nhớ.
// Leo cầu thang bottom-up, giữ 2 biến — O(n) thời gian, O(1) bộ nhớ
function climb(n) {
  if (n <= 2) return n;
  let a = 1, b = 2;                        // f(1) = 1, f(2) = 2
  for (let i = 3; i <= n; i++) [a, b] = [b, a + b];
  return b;
}
// Coin change: ít xu nhất — O(amt · số loại xu), O(amt) bộ nhớ
function coinChange(coins, amt) {
  const dp = Array(amt + 1).fill(Infinity); dp[0] = 0;
  for (let i = 1; i <= amt; i++) for (const c of coins)
    if (c <= i) dp[i] = Math.min(dp[i], dp[i - c] + 1);
  return dp[amt] === Infinity ? -1 : dp[amt];
}
console.log(climb(10), coinChange([1, 5, 6, 9], 11));   // 89 2
⚠ Bẫy phỏng vấn: Bẫy coin change: tham lam “lấy đồng lớn nhất trước” là sai. Với coins = [1, 5, 6, 9] và số tiền 11, greedy ra 9+1+1 = 3 đồng, còn đáp án đúng là 5+6 = 2 đồng. Greedy chỉ đúng với vài bộ mệnh giá đặc biệt.
💬 Nói thêm để ghi điểm: Trình bày DP theo đúng 4 bước: định nghĩa trạng thái (dp[i] nghĩa là gì) → công thức truy hồi → base case → thứ tự duyệt. Nói xong 4 bước rồi mới gõ code, người phỏng vấn theo được ngay.
