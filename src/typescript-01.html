Vì sao TS · any vs unknown vs never
?TypeScript giúp gì mà JavaScript không tự làm được?
?any và unknown khác nhau chỗ nào?
💡 Trả lời
  • TS là lớp kiểm tra lúc compile. Build xong type bị xoá sạch, runtime chỉ còn JS thuần — nên type không kiểm chứng được dữ liệu API lúc chạy.
  • Giá trị thật: bắt lỗi sớm, autocomplete, refactor an toàn, type là tài liệu sống. Bật strict mới có strictNullChecks — thứ chặn nhiều bug nhất.
  • any tắt mọi kiểm tra và lây lan: gán any sang biến khác là mất type ở đó luôn. unknown nhận mọi giá trị nhưng bắt narrow trước khi dùng.
  • never là tập rỗng, không giá trị nào thuộc kiểu này. Gặp ở hàm luôn throw, vòng lặp vô tận, và ở nhánh exhaustive check.
  • Muốn chắc dữ liệu runtime đúng type thì phải validate thật bằng Zod / io-ts rồi lấy type ra bằng z.infer — đừng tin mỗi as.
function handle(res: unknown) {
  // ❌ any: tắt hết kiểm tra, compile im lặng, runtime mới nổ
  const a = res as any;
  a.data.items.map((x: any) => x.id);

  // ✅ unknown: buộc narrow trước khi đụng vào
  if (typeof res === 'object' && res !== null && 'data' in res) {
    console.log(res.data);
  }
}

// never: hàm không bao giờ trả về giá trị
function fail(msg: string): never { throw new Error(msg); }
⚠ Bẫy phỏng vấn: Câu vặn hay gặp: “type có chặn được API trả sai dữ liệu không?” → Không. Type bay hết sau khi compile. Và as chỉ là lời hứa với compiler, nó không kiểm tra gì cả — sai là nổ lúc runtime.
